# 使用有上限的持续剧情线

故事作者需要在四次选择之后继续发展剧情，同时还要能在合适的位置带走可复用结果。我们决定把四回合从“固定终点”改为“首次可生成阶段回顾的最小长度”，允许作者在回顾后返回同一条剧情线继续，单个阶段最多接受十二个场景回合。

界面在故事舞台顶部展示选择轨迹：按顺序保留所有已接受行动与结果，并显示当前待选或推演草案节点。当前数据模型只维护一条已接受路线，因此不把它称为完整选择树，也不保存被拒绝草案或平行分支。

## Considered Options

- **固定四回合结束**：边界最清楚，但故事刚形成因果链就被迫停止，难以承载长篇蓝本。
- **无限继续**：交互自由，但会让会话、提示上下文和回顾结构持续膨胀。
- **持久化完整分支树**：能比较多条路线，但需要分支版本、切换、删除与合并语义，超出当前单路线状态模型。

## Consequences

回顾请求必须包含 4～12 个已接受回合；回顾是可重复生成的阶段快照，不再代表终局。十二回合上限让提示与浏览器会话保持有界。若以后需要完整选择树，应另行设计分支标识、父节点关系与切换规则，而不是把当前选择轨迹误当作分支存储。
