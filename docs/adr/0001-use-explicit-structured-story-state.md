# 使用显式结构化剧情状态

产品需要在四个场景回合中保持人物、关系与世界事实一致，同时把每次选择造成的变化解释给故事作者。我们决定以结构化的剧情状态作为已接受事实的唯一来源：模型针对某个行动返回推演草案及状态变化，只有作者接受后才提交为新的剧情状态；带修正意见重新推演时仍从同一份已接受状态开始。这比只依赖聊天记录更可控且可验证，也比为短篇或章节建立完整检索系统更符合九小时交付边界。

## Considered Options

- **完整聊天记录**：实现简单，但状态隐含在文本中，难以展示、校正和验证一致性。
- **完整小说检索系统**：能扩展到长篇内容，但会引入分段、召回与引用质量问题，偏离当前核心路径。

## Consequences

模型输出必须通过固定结构校验；推演草案和已接受状态必须严格分离。固定结构会牺牲一部分自由度，但让作者控制、错误恢复和最终回顾共享同一套可信事实。
